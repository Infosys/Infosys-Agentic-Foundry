IAF AgentOS - File Mode ASCII Flow

Two views of the same solution: a detailed engineering view and a simple business-friendly flow. File mode means the agent reads enterprise markdown context files at runtime instead of loading the full entity context from tables.

This view is for engineers and architects. It shows the main runtime paths, features, files read, files written, and accuracy notes for file mode. 
IAF AGENTOS - FILE MODE - END TO END VIEW
=========================================

WHAT FILE MODE MEANS
--------------------

Agent config:
  enterprise_root/tenants/company/agents/enterprise_agent/config.yaml

  context_loading_mode: file
  context_file_path: /shared/Enterprise_Context.md

Meaning:
  - The router still chooses the best skill.
  - The router LLM extracts entity_name and entity_type from the user query.
  - The agent does NOT preload the full entity tree from SQLite.
  - The agent is instructed to read markdown files:
      /shared/Enterprise_Context.md
      linked /shared/contexts/*.md files
      linked policy/playbook/database notes
      optional entity notes files
  - The agent answers from those files and tool results.

FILE MODE CONTEXT READING
-------------------------

Prompt tells the agent:
  cat "/shared/Enterprise_Context.md"

  /shared/Enterprise_Context.md
    -> enterprise_root/tenants/company/shared/Enterprise_Context.md

Then agent follows links like:

  /shared/contexts/taxonomy/*.md

  Agent can read shared business context.
  Agent cannot write to shared context through normal tool paths.

EXECUTION MODES
---------------

react
  Normal LLM + tool loop.
  Best for open-ended questions.

workflow
  Fixed ordered steps from SKILL.md.
  Best for repeatable business procedures.

parallel
  DAG-style steps run concurrently where possible.
  Best for independent data gathering.

supervisor
  One meta-skill delegates to worker skills.

orchestrator
  Auto-selected when router sees a multi-step request.
  Sequential skill chaining.

planned
  Auto-selected when router sees multiple unrelated domains.
  Creates a plan/DAG and waits for plan approval/execution.

MAJOR FEATURES IN THE SOLUTION
------------------------------

1. API chat
   Simple HTTP request/response agent calling.

2. WebSocket chat
   Streaming chat with progress, reasoning, tools, HITL, and final response.

3. File-mode context loading
   Enterprise markdown context is read at runtime.

4. Skill router
   Selects skill, entity, complexity, execution mode.

5. Taxonomy signal index
   Uses L5 activity taxonomy to improve skill/domain routing.

6. SafeKernel
   Sandboxed tool execution with virtual paths, audit, rate limits, and approval gates.

7. Skill system
   Capabilities are defined as SKILL.md files, not hardcoded Python.

8. Multiple execution modes
   react, workflow, parallel, supervisor, orchestrator, planned.

9. Memory
   Conversation history, knowledge graph, plan cache, similar episode search.

10. Human-in-the-loop
    Approval works in chat, queue, and cron paths.

11. Command Center queue
    Autonomous background job processor with retries, DLQ, step history.

12. Cron scheduler
    Redis-backed recurring jobs with manual run and run history.

13. Telemetry
    Trace DB, tool spans, token/cost tracking, Digital Twin events.

14. FinOps
    Cost/token analytics by model, skill, and purpose.

15. Hooks
    Declarative pre/post step and tool hooks for audit and circuit breaking.

16. MCP/tool extension
    Skills can connect to external MCP tools.

17. Multi-tenant layout
    Platform code is separated from tenant data, skills, context, memory.

18. Skill Builder / Doc-to-Skill
    UI can author skills and generate SKILL.md packages from documents.


ACCURACY CRITIQUE / IMPORTANT CORRECTIONS
-----------------------------------------

1. The docs say file mode has "no SQLite lookups".
   More accurate:
     file mode skips the full entity_registry.collect_context() pre-signal,
     but agent.py can still call entity_registry.resolve_entities()
     to map an extracted entity name to a node_id for query_memory.

2. REST /api/chat may have a file-mode bug.
   In chat.py, _entity_store_http is assigned only inside the table-mode branch,
   but later referenced during routing signal logging.
   In file mode that can become an UnboundLocalError, although it is inside a try.

3. Cron does not go through /api/chat or /ws/chat.
   Cron creates SafeKernel + SkillAgent directly in shared/state.py.
   File mode still applies because the same agent config is loaded.

4. Queue does not go through /api/chat or /ws/chat either.
   Queue processor calls SkillAgent.run() directly in a background thread.
   File mode still applies through the same enterprise_agent config.

5. Direct cron still writes a Command Center summary row.
   The docs say direct cron does not use the queue monitor for the main run.
   Code also inserts a summary item into command_center.db after successful cron execution.

6. File mode is easier to set up, but not "no database at all".
   It avoids database-backed context loading.
   The system still uses SQLite/Redis for memory, traces, queue, cron, sessions, approvals, and telemetry.

7. /shared is read-only to the agent.
   File mode is meant for reading enterprise context, not modifying it during normal execution.

IAF AGENTOS - FILE MODE - SIMPLE ENGLISH FLOW
=============================================

BIG IDEA
--------

File mode means:

  The agent uses files as its business knowledge base.

  Instead of first loading a big database of business context,
  the agent opens the main enterprise context file,
  follows the links inside it,
  reads the right policy/playbook/data files,
  and then answers.

WHAT THE ROUTER DOES
--------------------

User says:
  "What should we do for this overdue customer invoice?"

Router asks:
  What skill should handle this?
  Which business area is this?
  Is there a customer, vendor, invoice, ticket, or system name?
  Is this simple, multi-step, or cross-domain?

Router returns:
  skill = the best skill
  entity = the customer/vendor/etc. mentioned
  mode = how the agent should run


WHAT THE AGENT DOES NEXT
------------------------

Agent receives:
  question
  selected skill
  entity name
  file-mode instruction

Then it follows this rule:

  First read:
    /shared/Enterprise_Context.md

  Then read:
    the relevant linked files

  Then use:
    tools if needed

  Then answer:
    based on the files and tool results


WHY ENTERPRISE_CONTEXT.MD IS IMPORTANT
--------------------------------------

Think of Enterprise_Context.md as the front desk or map.

It tells the agent:
  where business knowledge lives
  which domain files exist
  which policies matter
  which playbooks to follow
  which databases or data files may be useful

The agent starts there first.


SAFE TOOL USE
-------------

The agent cannot freely touch the computer.

Every tool call goes through a safety layer.

Safety layer checks:
  Is this path allowed?
  Is this command allowed?
  Is this trying to delete or modify something risky?
  Does a human need to approve this first?
  Should this action be audited?

Only then does the command run.

IF A QUEUE ITEM RUNS
--------------------

Best for:
  background work
  external system tickets
  batch jobs
  retry and DLQ handling
  monitored autonomous work

Flow:

External system creates queue item
  |
  v
Queue stores it
  |
  v
Processor claims it
  |
  v
Router picks skill
  |
  v
Agent runs
  |
  v
Progress steps are saved
  |
  v
Item becomes:
    done
    awaiting_human
    or dlq


WHAT GETS SAVED
---------------

For normal chat:
  conversation history
  tool usage
  reasoning context
  learned patterns
  trace details
  audit logs

For queue:
  queue item status
  execution record
  step-by-step progress
  retry or DLQ status

For cron:
  job definition
  run history
  result summary
  optional approval checkpoint

For all modes:
  safety/audit records
  telemetry when enabled

ONE-LINE SUMMARY
----------------

In file mode, IAF AgentOS is a safe enterprise agent system where
questions, API calls, cron jobs, and queue jobs all reach the same
agent engine, and the agent answers by reading enterprise markdown
context files plus any linked business data, while approvals, memory,
audit, queue, cron, and telemetry run around it.

Simple view: suitable for walkthroughs with business users, managers, and non-engineering stakeholders.
