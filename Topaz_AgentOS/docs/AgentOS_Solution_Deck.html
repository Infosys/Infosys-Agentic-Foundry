Design Time vs Runtime

🛠️
Design Time
Author the domain — what the platform knows and is allowed to do.
  • ✓ Author Skills (domain packs) — form builder, Skill Designer (natural language / Dev Mode), or the visual Graph Studio
  • ✓ Curate Enterprise Context — context packages, entities & taxonomy, knowledge base
  • ✓ Define approval policy — DOA / judgment matrices & approval rules
  • ✓ Configure governance hooks (platform + tenant) and entitlements / RBAC
  • ✓ Register providers — LLMs, MCP tools, enterprise APIs, telemetry
  • ✓ Validate & publish per tenant
⚡
Runtime
Execute the work — autonomously, but under control.
  • ✓ Route each request to the right skill (keyword + semantic/taxonomy)
  • ✓ Run in 8 execution modes — React · Workflow · Parallel · Supervisor · Orchestrator · Planned · RLM · Graph
  • ✓ Screen every tool call; pause for human approval (propose-then-apply) when policy says so
  • ✓ Work autonomously via Cron · Queue · Mission/Workstreams · Deterministic Automations
  • ✓ Ground & cite answers from knowledge + context (evidence & sources)
  • ✓ Learn & compound — feedback, self-critique, and an opt-in RL/eval capture loop

Enterprise Fit — customization per layer

The platform ships domain-agnostic. Each layer below shows the customization & integration an enterprise applies on adoption — tagged by type and primary owner.

CONFIG set values, no code · INTEGRATE connect an enterprise system · AUTHOR create domain content · POLICY define rules / approvals

🗂️ The biggest customization is your Enterprise Context

Curated domain knowledge — Enterprise_Context.md, context packages, entities & taxonomy, DOA / judgment matrices, knowledge base, business data. It feeds Orchestration (routing), Agent Engine (skills), Governance (approvals) and the Kernel (data) — and is what makes the platform yours. Swap it → same engine, new domain.

Capabilities in depth

Every capability below is built into the platform and spans multiple layers.

🧭

Reasoning & Autonomy

  • 8 execution modes: React · Workflow · Parallel · Supervisor · Orchestrator · Planned · RLM · Graph
  • RLM reasoning-as-code over governed tools
  • Stored process graphs — verifier nodes + convergence loop
  • Autonomous queue + cron + Mission/Workstream backlogs
  • Multi-signal skill routing (WHO + WHAT + keyword)
🛡️

Trust & Control

  • Human-in-the-loop approvals (warm continue + durable resume)
  • Approval rules & DOA / judgment matrices
  • Tool-call governance firewall (Pre/PostToolUse hooks)
  • Entitlements / RBAC + service principals
  • Full audit trail on every action
🧠

Learning & Memory

  • Episodic + knowledge memory · RAG · entity resolution
  • Continuous / implicit learning → knowledge promotion
  • Feedback (👍/👎, plan feedback) & self-critique · self-evolution
  • Opt-in RL/eval capture → SFT / DPO / RFT datasets
  • Trace-value routing + eval suites & promotion gates (human-gated)
🔍

Explainability

  • Evidence bundles + cited sources
  • Reasoning & execution step traces
  • Operational "digital twin" telemetry
  • OTLP export to enterprise observability
🧩

Extensibility

  • Authoring lifecycle: draft → validate → review → publish
  • Skill Builder · Skill Designer (NL/Dev Mode) · Graph Studio (visual)
  • Skill Packs — import/export across tenants
  • Ports-and-adapters: swap LLM / tools / policy / telemetry · MCP
  • Multi-tenant isolation · enterprise integration
🗂️

Enterprise Context

  • Per-tenant curated domain knowledge
  • Grounds reasoning & makes answers explainable
  • Drives routing (taxonomy), RAG, and DOA-based approvals
  • Swap enterprise_root → same engine, new domain
🕸

Process Graphs & RLM

  • Graph mode — stored DAG of skill-nodes + verifier + convergence loop
  • Escalate-to-human on exhaustion; independent-verifier grounding
  • RLM — reasoning-as-code with an AST guard + governed tools
  • Propose-then-apply: side effects become HITL approval cards
  • Authored visually in Graph Studio or from English
📈

Private Learning Loop

  • Opt-in RL/eval capture (trajectories, model/tool calls, signals)
  • Trace-Value Router — which traces are worth learning from
  • Eval suites, golden sets & promotion gates
  • Exporters: SFT · rejection-SFT · DPO · KTO · RFT
  • Human-gated & private — never auto-trains
🔁

Autonomous Operations

  • Workstreams / Mission Mode — process item backlogs on a schedule
  • Per-item state, retries, HITL & evidence bundles
  • Cron scheduler (Redis-backed) + Command Center queue (DLQ)
  • Deterministic Automations — no-LLM shell/python pipelines
👁

Live Observability

  • Per-turn thinking box — live step narration, collapses to "Thought for Ns"
  • Execution trace + evidence bundles (what grounded the answer)
  • FinOps — per-call token & cost attribution
  • Operational digital twin + OTLP export

These are grounded in the as-built platform (Redis + SQLite, FastAPI + Alpine.js UI, native React runtime, agent_os kernel). Provider/scale targets (e.g. message bus, multi-cloud) are roadmap and intentionally not shown here.
