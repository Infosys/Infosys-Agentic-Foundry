Layer 3 · SkillAgent · 4 Execution Engines · ReAct + Native Runtimes

execution.py · react_runtime/ · planner.py · plan_critic.py · progress_phases.py
EXECUTION

WorkflowEngine

Deterministic steps
  • No LLM between steps
  • Config-driven sequence
  • Best for SOP-shaped work

ParallelEngine

DAG, concurrent
  • Dependency-resolved fan-out
  • Async tool execution
  • Best for independent lookups

SupervisorEngine

Fan-out · fixed
  • Manager + workers
  • SKILL.md declares workers
  • Best for multi-domain queries

OrchestratorEngine

LLM-driven adaptive
  • Manager loop chooses next skill
  • Goal-driven dispatch
  • Best for open-ended work

React Runtime Factory

react_runtime/factory.py
  • Native Azure Responses path
  • Native Anthropic thinking path
  • LangGraph fallback otherwise

Planner · PlanCritic

  • DAG planner for multi-step
  • Plan validator (feasibility)
  • Re-plan on hook block

Progress Phases

  • analysis → execution → validation → completion
  • Status streamed to /ws/chat

Layer 4 · Hook Runner · 4 Authorable Phases + ~20 Platform Event Junctions

hook_runner.py · hook_context.py · hook_approval.py · platform_hooks/ · policy_control.py · trace_callback.py · tool_governance.py
HOOKS
A · USER-AUTHORABLE LIFECYCLE PHASES (declared in config.yaml)

PreToolUse

SYNC · can block
  • Fires before every tool call
  • Approve dangerous ops
  • Returns {blocked, reason}
  • Routes to HITL queue if needed

PostToolUse

ASYNC fire-and-forget
  • Fires after tool completes
  • Audit log · Splunk · result check
  • Non-blocking

PostTurn

SYNC · can block
  • Fires before HTTP response
  • PII redaction · compliance
  • Can modify or block response

PostSampling

ASYNC background
  • After response sent
  • Analytics · feedback · Slack
  • Non-blocking
B · PLATFORM EVENT JUNCTIONS (fired by the runtime · subscribable via platform_hooks/ · gated by policy_control · emitted as spans by trace_callback)

Routing & Plan

  • Skill-route decision (TaxonomySignalIndex)
  • Plan critic validate
  • Pre-step / Post-step per workflow step
  • Progress phase transition (analysis → exec → validate → done)

Tool & Credential

  • Tool governance pre-check
  • Credential access (name only, no value)
  • External access entitlement (HTTP / DB / MCP)
  • SQL connection governance
  • SafePath virtual → real rewrite

Data & Memory

  • Memory write + VectorStore auto-index
  • Knowledge extraction trigger
  • Knowledge confirm / reject
  • Entity registry resolution
  • Atomic IO read-modify-write

Workstream & Approval

  • Workstream item state transition
  • Queue claim · DLQ move
  • Approval rule eval
  • Approval decision (approve / reject)
  • Cron tick

LLM & Telemetry

  • LLM call (token / cost tracker)
  • Trace span open / close per type
  • Telemetry fanout (OTLP / Datadog / Splunk)
  • Twin KPI emit
  • Response composition

Hook Context env (passed to scripts)

  • IAF_HOOK_PHASE · IAF_TOOL_NAME · IAF_TOOL_INPUT
  • IAF_TOOL_OUTPUT · IAF_AGENT_ID · IAF_SKILL_NAME
  • IAF_TENANT_ID · IAF_USER_ID · IAF_REQUEST_ID
  • IAF_SKILL_CONTEXT JSON blob

Approval Rules · approval_rules.py

  • always_require · never_require
  • thresholds · numeric operators
  • conditions · keyword patterns
  • Urgency: critical · high · medium · low

Why this matters

  • Every junction = labeled span in traces.db
  • Every junction = candidate reward channel for RL
  • Every junction = policy-enforcement point
  • Every junction = audit / compliance evidence
  • Compare: DeepAgents has only 4 middleware wrap points

Layer 7 · Workstream Runtime · HITL · CC Queue · Cron

mission_engine.py · workstream_store.py · approval_store.py · cc_queue/ · scheduler/
ORCHESTRATION

MissionEngine · run_iteration()

  • One workstream item per tick
  • Status: pending → in_progress → done / awaiting_human / failed
  • Priority strategies: sequential · highest_amount · highest_aged · round_robin
  • Retries with max_retries cap
  • Result includes trace_id, approval_id, duration_ms

CC Queue · QueueProcessor

  • Background loop polls cc_queue.db
  • Atomic claim → status=in_progress
  • Routes via SkillRouter
  • Pause on HITL · resume on decision
  • Result writes result_summary + job_steps
  • Dead-letter queue (dlq) after max retries

HITL Approval Store · Redis

  • Key approval:<id>
  • tenant · user · skill · tool · args (redacted)
  • reason · urgency · created_at · resolved_at
  • decision · approve / reject · decision_note
  • Streams to /ws/approvals

Workstream Runtime DB

  • workstream_runtime.db SQLite
  • status: running · paused · completed · failed
  • total_items · completed_items
  • Independent of YAML persistence

Cron Scheduler

  • APScheduler in studio process
  • Per-tenant jobs
  • Triggers mission iteration or cc_queue feed
  • scheduler/ module
